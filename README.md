# GiveFlpps

لوحة تعرض **أكثر 100 لعبة لديها مسابقات (Giveaways) نشطة وقابلة للدخول الآن**
على موقع [SteamGifts](https://www.steamgifts.com) — أي: لكل لعبة نحسب **كم
مسابقة نشطة حالياً** لها في نفس اللحظة (مثال: "The Walking Dead" لديها 6
مسابقات مفتوحة للدخول الآن)، ونرتّب الألعاب حسب هذا العدد تنازلياً. لكل لعبة
نعرض أيضاً إجمالي عدد المشاركين عبر كل نسخها، أقل نقاط دخول، الحد الأدنى
للمستوى، وأقرب موعد انتهاء — مع إمكانية توسيع الصف لرؤية كل نسخة (مسابقة) على
حدة والدخول إليها مباشرة.

الموقع غير رسمي وغير تابع لـ SteamGifts — هو أداة تجميع بيانات (aggregator)
بواجهة مستقلة.

## كيف يعمل المشروع

```
giveflpps/
├── netlify.toml                     إعدادات Netlify (النشر + الدوال + الجدولة)
├── package.json
├── netlify/functions/
│   ├── lib/
│   │   ├── scraper.js               محرّك الاستخراج + التجميع حسب اللعبة والترتيب
│   │   ├── sync-runner.js           منطق "اجلب وخزّن" المشترك بين الجدولة والتحديث اليدوي
│   │   └── store.js                 طبقة التخزين (Netlify Blobs)
│   ├── sync-giveaways.js            دالة مجدولة تعمل كل 30 دقيقة تقريباً (لا تُعدّل بنيتها)
│   ├── get-giveaways.js             الـ API العام الذي تستدعيه الواجهة
│   └── refresh.js                   تحديث يدوي فوري (محمي بكلمة سرّ)
├── public/
│   ├── index.html / styles.css / app.js   الواجهة الأمامية
└── scripts/test-parser.js           اختبار محرّك الاستخراج + الترتيب بدون إنترنت
```

**الفكرة الأساسية:** دالة مجدولة (`sync-giveaways`) تجلب عدة صفحات من قائمة
مسابقات SteamGifts، **تجمّع النتائج حسب اللعبة** (وليس حسب المسابقة
الفردية)، تحسب لكل لعبة عدد مسابقاتها النشطة الآن، وتخزّن أفضل 100 لعبة في
**Netlify Blobs** (تخزين مدمج مع Netlify، يعمل تلقائياً بدون أي إعداد
إضافي). بعدها، كل زيارة للموقع تقرأ دالة `get-giveaways` هذه النسخة
المخزَّنة فوراً — لا يحدث أي "سحب مباشر" من SteamGifts عند كل زيارة.

> **حدّ مهم بخصوص التغطية:** مسابقات SteamGifts النشطة مرتّبة افتراضياً حسب
> الأقرب انتهاءً، وليست مجمّعة حسب اللعبة، وقد يتجاوز عددها الإجمالي ما
> نفحصه من صفحات في كل مزامنة (`SYNC_MAX_PAGES`، افتراضياً 18 صفحة ≈
> 350-450 مسابقة). فالعدد الذي نعرضه لكل لعبة هو **عدد نسخها النشطة ضمن ما
> فحصناه**، وليس بالضرورة كل ما هو موجود فعلياً على الموقع في تلك اللحظة —
> وهذا محسوب عمداً ليبقى الفحص سريعاً ومهذّباً تجاه SteamGifts. يمكنك رفع
> `SYNC_MAX_PAGES` لتغطية أوسع (راجع قسم "الإعدادات" لملاحظة حدود وقت
> التنفيذ).

### كيف يتم "الاستخراج" (Scraping) تحديداً

بدل الاعتماد على أسماء أصناف CSS (classes) التي قد تتغيّر مع أي تحديث
تصميمي لموقع SteamGifts، يعتمد `scraper.js` على شيء أكثر ثباتاً: **بنية
الروابط**. كل صف مسابقة يحتوي دائماً على رابط لصفحة المسابقة
(`/giveaway/{code}/{slug}`)، ورابط لعدد المشاركين
(`/giveaway/{code}/{slug}/entries`)، ورابط لصفحة اللعبة (`/game/{code}/{slug}`
— هذا تحديداً هو المفتاح الذي نستخدمه للتجميع حسب اللعبة)، ورابط للمستخدم
صاحب العرض (`/user/...`). يحدّد الكود صفّ كل مسابقة عبر هذه الروابط، ثم يقرأ
الأرقام مباشرة من النص الظاهر للمستخدم ("507 entries"، "(30P)"،
"Level 2+"، "3 hours remaining"). بعدها تُجمَّع كل المسابقات المستخرجة حسب
مفتاح اللعبة (`gameCode`)، ويُحسب لكل لعبة عدد النسخ الحالية
(`activeGiveawaysCount`) وإجمالي الدخول (`totalEntries`)، ثم تُرتَّب الألعاب
حسب عدد النسخ تنازلياً (والتعادل يُكسر بإجمالي الدخول).

> **ملاحظة مهمة وأمانة:** لا يوجد لـ SteamGifts واجهة برمجية (API) رسمية
> عامة، لذا هذا المشروع يعتمد على قراءة صفحاتهم العامة (نفس ما يراه أي
> زائر عادي بدون تسجيل دخول). يُرجى الاطلاع على
> [شروط الاستخدام](https://www.steamgifts.com/legal/terms-of-service)
> الخاصة بهم قبل النشر العلني الواسع، والإبقاء على معدّل الطلبات منخفضاً
> (القيم الافتراضية هنا متحفظة عمداً — راجع قسم "الإعدادات" أدناه). هذا
> المشروع لأغراض شخصية/مجتمعية للاطلاع فقط، وليس بديلاً لحساب SteamGifts
> ولا يقوم بالدخول في المسابقات نيابة عنك.

## التشغيل محلياً

```bash
npm install
npm run test:parser   # يتحقق من الاستخراج + التجميع حسب اللعبة، بدون إنترنت
npx netlify dev       # يشغّل الموقع + الدوال محلياً على http://localhost:8888
```

`netlify dev` يحتاج [Netlify CLI](https://docs.netlify.com/cli/get-started/)
(`npm install -g netlify-cli` إن لم يكن مثبّتاً).

## النشر على Netlify

### الطريقة الأسهل: عبر GitHub

1. ارفع هذا المجلد إلى مستودع GitHub (أو GitLab/Bitbucket).
2. من لوحة Netlify: **Add new site → Import an existing project** واختر
   المستودع.
3. Netlify سيقرأ `netlify.toml` تلقائياً (مجلد النشر `public`، ومجلد الدوال
   `netlify/functions`) — لا حاجة لتغيير أي إعداد بناء (build settings).
4. بعد أول نشر، اذهب إلى **Site configuration → Environment variables**
   وأضف (اختياري لكن مُستحسن):
   - `SCRAPER_CONTACT` — بريدك الإلكتروني أو رابط تواصل، يُضاف داخل
     الـ User-Agent الذي يرسله البوت (ممارسة مهذّبة تجاه SteamGifts).
   - `REFRESH_SECRET` — كلمة سرّ عشوائية طويلة، لتفعيل مسار التحديث اليدوي
     `/api/refresh?secret=...` (بدونها هذا المسار يبقى معطّلاً تلقائياً).
5. من تبويب **Functions**، تأكد أن `sync-giveaways` تظهر كدالة مجدولة
   (Scheduled). أول تشغيل لها سيكون بعد نشر الموقع بحسب الجدول (كل 30
   دقيقة)، لكن أول زائر للموقع قبل ذلك سيحصل على نتائج فورية لأن
   `get-giveaways` تقوم بعملية استخراج أصغر تلقائياً إن لم تجد بيانات
   مخزَّنة بعد (انظر `BOOTSTRAP_MAX_PAGES`).

### أو عبر Netlify CLI مباشرة من جهازك

```bash
npm install -g netlify-cli
netlify login
netlify init            # يربط المجلد بموقع Netlify جديد أو موجود
netlify deploy --prod
```

### Netlify Blobs

لا حاجة لأي إعداد يدوي — Netlify Blobs مفعّل تلقائياً لأي موقع على
Netlify منذ 2024، ومكتبة `@netlify/blobs` تكتشف بيانات الاتصال تلقائياً
عند التشغيل داخل دالة Netlify فعلية. لا تحتاج مفاتيح API ولا قاعدة بيانات
خارجية. **حتى لو تعطّل التخزين لسبب ما، الموقع يستمر بالعمل** — الدوال هنا
مكتوبة بحيث لا يوقف فشل الكتابة/القراءة في Blobs عملية العرض، بل يُسجَّل
الخطأ فقط في سجلّات الدالة.

## الإعدادات (Environment Variables) — كلها اختيارية

| المتغيّر | الافتراضي | الوصف |
|---|---|---|
| `SYNC_MAX_PAGES` | `18` | عدد صفحات SteamGifts التي تُفحص في كل مزامنة مجدولة |
| `SYNC_CONCURRENCY` | `6` | عدد الطلبات المتزامنة أثناء الفحص (أقل = أهدأ على SteamGifts، أبطأ لك) |
| `BOOTSTRAP_MAX_PAGES` | `4` | عدد الصفحات في أول تشغيل تلقائي (قبل أول مزامنة مجدولة) — أصغر عمداً لضمان استجابة سريعة |
| `TOP_N` | `100` | عدد الألعاب المحفوظة في القائمة |
| `SCRAPER_CONTACT` | (فارغ) | يُضاف داخل الـ User-Agent |
| `REFRESH_SECRET` | (فارغ = معطّل) | كلمة سرّ لتفعيل `/api/refresh` |

> **تنبيه بخصوص جدول التحديث (كل 30 دقيقة):** خلافاً للمتغيّرات أعلاه، لا
> يمكن التحكم بجدول المزامنة عبر environment variable، لأن Netlify يحتاج
> معرفة الجدول وقت البناء (build time) ليسجّله في بنيتها التحتية — وليس
> فقط كسلوك وقت التشغيل. لتغييره: عدّل القيمة الحرفية `"*/30 * * * *"` في
> **مكانين معاً** (يجب أن يتطابقا):
> `netlify/functions/sync-giveaways.js` (داخل استدعاء `schedule(...)`
> مباشرة) و `netlify.toml` (سطر `schedule = ...`)، ثم أعد النشر.

> **حد زمني للدوال:** الخطة المجانية في Netlify تُنهي أي دالة عادية بعد
> ثوانٍ معدودة (والدوال المجدولة عادة تحصل على مهلة أطول قليلاً). القيم
> الافتراضية أعلاه (مع مهلة 8 ثوانٍ لكل صفحة ومعالجة متزامنة) محسوبة لتبقى
> ضمن حدّ آمن. إن رفعت `SYNC_MAX_PAGES` كثيراً وبدأت المزامنة تفشل أو
> تنتهي بأقل من العدد المتوقّع من الصفحات، افتح **سجلّات الدالة (Function
> logs)** لـ `sync-giveaways` في لوحة Netlify — كل صفحة فشلت تُسجَّل هناك
> برسالة توضّح السبب (HTTP خطأ، تجاوز المهلة الزمنية، أو صفحة حظر آلي).

تغيير أي متغيّر: **Site configuration → Environment variables** في لوحة
Netlify، ثم أعد النشر (Redeploy) ليتم تطبيقه.

## لو ظهرت رسالة "تعذّر جلب البيانات" في الموقع

الواجهة الآن تعرض رسالة الخطأ الفعلية القادمة من الخادم (وليس نصاً عاماً
فقط)، فابدأ بقراءتها. الأسباب الشائعة:

1. **حظر آلي مؤقت من SteamGifts (الأرجح):** إن كانت الرسالة تذكر "بوت-تشالنج"
   أو "block page"، فهذا يعني أن SteamGifts أعادت صفحة تحدٍّ (مثل Cloudflare)
   بدل المحتوى الحقيقي. هذا خارج عن تحكّم الكود نفسه؛ جرّب `/api/refresh`
   بعد بضع دقائق، وإن استمر لفترة طويلة، قد تحتاج لتقليل `SYNC_CONCURRENCY`
   لتبدو الطلبات أقل آلية.
2. **مشكلة تخزين (Blobs):** افتح سجلّات دالة `get-giveaways` في Netlify —
   إن ظهرت رسالة "failed to read/write snapshot"، تأكد أن الموقع منشور
   فعلياً على Netlify (وليس فقط `netlify dev` محلياً بدون ربط) لأن Blobs
   يحتاج سياق موقع حقيقي على Netlify ليعمل.
3. **انتهاء المهلة الزمنية:** إن ذكرت الرسالة "timed out"، فهذا يعني أن
   الصفحة استغرقت أطول من `timeoutMs` — نادر الحدوث، لكن يمكن رفع القيمة
   داخل `netlify/functions/lib/scraper.js` إن تكرر كثيراً.

في كل الحالات، **سجلّات الدوال في لوحة Netlify** (Functions → اسم الدالة →
Logs) هي مصدر الحقيقة؛ الرسالة المعروضة في الواجهة مأخوذة مباشرة من هناك.

## التخصيص

- **الألوان والخطوط:** كل شيء في `public/styles.css` معرّف كمتغيّرات CSS
  أعلى الملف (`--bg-0`, `--ember`, `--teal`, `--font-ui`, `--font-num`...)
  — غيّرها من مكان واحد.
- **معيار الترتيب الافتراضي:** حالياً "الأكثر عدد نسخ نشطة" لكل لعبة
  (`activeGiveawaysCount` تنازلياً، والتعادل يُكسر بـ `totalEntries`).
  لتغييره، عدّل `rankGamesByActiveGiveaways` في
  `netlify/functions/lib/scraper.js` و/أو أزرار الفرز في `public/index.html`
  + `public/app.js`.
- **اسم الموقع:** غيّر "GiveFlpps" في `public/index.html` (العلامة
  والعنوان) — لا يوجد أي مكان آخر يعتمد على الاسم.

## لو توقف الاستخراج عن العمل مستقبلاً (SteamGifts غيّرت تصميمهم)

1. شغّل `npm run test:parser` — إن فشل، فهذا يعني أن أحد الأنماط
   (patterns) في `netlify/functions/lib/scraper.js` لم يعد يطابق الصفحة
   الحقيقية.
2. افحص صفحة `https://www.steamgifts.com/giveaways/search` يدوياً (View
   Source)، وقارن بنية الروابط مع الثوابت في أعلى `scraper.js`
   (`TITLE_HREF_RE`, `GAME_HREF_RE`, إلخ) والتعابير النمطية للنصوص
   (`POINTS_RE`, `ENTRIES_TXT_RE`...).
3. حدّث الثوابت المطلوبة فقط، ثم أعد تشغيل `npm run test:parser` مع تحديث
   `fixtures/sample-listing-page.html` إن لزم، للتأكد قبل النشر.
